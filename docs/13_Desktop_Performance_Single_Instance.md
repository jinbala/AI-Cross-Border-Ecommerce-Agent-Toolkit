# 桌面性能与单实例 · 2026-10-17

本次解决两个问题：重复双击产生多个主窗口，以及经营页面每次请求都重新启动 Python 后台、打开 SQLite 带来的等待。适用于整合桌面版 2.0。

## 使用效果

打开方式沿用根目录启动脚本或桌面版 EXE。首次打开创建主窗口；后续启动直接退出新进程，并通知已有窗口显示、恢复最小化状态及激活。已有窗口最大化时保持最大化。`--open-compass` 请求转交现有窗口。按 Windows 用户和登录会话隔离，程序路径不参与识别，因此不同目录的新版程序也只开一个窗口。

限制适用于采用本次实现的整合程序，旧版 1.3 或尚未更新的旧 EXE 不识别这项锁。业务资料仍使用首次启动程序自己的数据目录。

## 实现

- `PantsWorkbench.cs` 中的 `SingleInstance` 使用命名 Mutex 持有应用生命周期锁，两个 AutoResetEvent 分别通知激活和罗盘入口。等待在线程池执行，窗口操作派发回 UI 线程；启动阶段尚未进入消息循环时也可保留通知。关闭释放锁，进程异常退出可恢复。
- `BusinessBridge.cs` 为普通请求保留一个后台进程，用 `SemaphoreSlim` 排队；输入输出为 UTF-8 逐行 JSON。首次进入经营功能才创建后台，不影响仅使用榜单时的启动。
- `service.py --serve` 复用 Store / SQLite 连接，逐请求返回并刷新输出；错误不终止后续请求，超限行完整丢弃后恢复帧边界。原单次调用仍可用。
- AI 生成保留独立进程和原超时，以免模型等待占住普通请求队列。普通后台超时或断开后丢弃当前连接，下次用户操作重新创建；不会自动重放可能已落库的写入。
- 主窗口关闭时结束其后台；不新增监听端口。数据库内容仍按原逻辑提交，不因待命而延迟保存。
- 发布版不周期访问 `source-path.txt`；开发源文件确实存在时才执行源页面检测。定时登录检测增加重入保护。

| 检查 | 结果 |
|---|---|
| Python 单元及协议测试 | 63 项通过 |
| 裤装 Node 测试 | 55 项通过 |
| 单实例 | 最小化恢复、另一解压目录启动、连续 8 次启动、罗盘请求转交、正常重开及崩溃后重开通过 |
| 整合桌面流程 | 实际商品按钮、候选建档、利润、工作流、测款、视频与评论检查通过 |
| 持续后台 | 连续复用、错误后继续、并发排队、杀掉隔离后台后恢复且业务数据一致通过 |

独立测试对旧包后台重复运行 5 次 `state`，新后台预热一次后连续运行 20 次 `state`。空白隔离数据库的单次调用中位数为 **443.51 ms**，待命后台为 **0.35 ms**。整合桌面消息桥另测 10 次连续读取共 **33 ms**。这些结果只描述本机后台请求开销，不代表整页渲染、首次打开、在线采集或模型生成的整体加速比例。记录保存在本机忽略目录 `desktop_app/.build/unified/tests/`。

复测：

```powershell
python -m unittest discover -s desktop_app/tests -q
node --test --test-reporter=dot integrations/pants/tests/*.test.mjs
python unified_desktop/check_runtime.py
python unified_desktop/check_release.py
```

`check_runtime.py` 使用独立的命名锁、临时测试窗口及空白数据库；`check_release.py` 使用隔离 WebView 和演示业务资料。二者不读取真实账号、不消耗模型额度。运行原生窗口检查需要正常 Windows 桌面环境。
