# 列表与页面性能 · 2026-10-17

本轮继续优化主窗口内的重复渲染、大资料读取和列表节点数量。沿用上一轮的后台待命与单实例限制。

## 操作变化

- 桌面商品榜每页 80 款，上一页 / 下一页切换；总数显示完整筛选结果。搜索和筛选先作用于全部商品，再显示当前页。收藏操作保持当前页，筛选改变回到第一页。
- “我的候选”和“成果资料”每页 50 条。候选搜索覆盖所有候选，连续输入合并处理并保留焦点。分页不删除记录。
- 成果目录只读取名称和类型，点击“查看”才读取正文，复制和导出使用该完整正文。
- 商品 HTML 清单点击导出才生成，导出范围仍为全部符合当前条件的商品，包括其他页。CSV / JSON 保留原来的完整筛选范围。

## 性能实现

`local_tool_app.js` 取消桌面商品榜的隐藏 iframe 全文预览，避免同一批商品同时渲染为卡片和隐藏整页。图文榜及原浏览器版本的预览仍可用。商品搜索文本用 WeakMap 复用，工厂初筛结果在一次过滤和卡片渲染之间复用。

`state_cache.mjs` 缓存经营页面状态 15 秒，并合并并发读取。写请求发出和返回时都失效；过期、显式刷新或保存后重新读取。缓存带代次检查，写入前启动的旧读取不能覆盖新状态。前端只缓存经营页面资料，不缓存模型密钥；模型生成完成后也会失效。

`state(compact=true)` 返回列表摘要，`artifact_detail` 根据记录类型校验后返回一份正文。原完整 `state` 协议保持兼容；候选详情由原 `candidate_brief` 从完整记录生成。

SQLite 增加 `record_list_cache_v1` 和按类型 / 更新时间的索引。首次升级从原记录补建摘要；之后插入、更新和删除在原事务内同步触发器维护，经典客户端或其他数据库连接写入也可更新摘要。查询无需逐页扫描大段报告和来源历史。完整记录仍由原 `records` 表保存，JSON 备份与恢复按原口径处理；摘要是可重建数据，不加入 JSON 备份。

## 测量与验证

使用人工构造的 500 个候选、200 份长报告，完整 JSON 响应为 43,577,669 字节，摘要为 178,569 字节，减少 99.59%。本机连续五次测量，读取并序列化的中位耗时从 579.46 ms 降到 8.12 ms。该结果仅用于比较这份模拟数据的本地列表开销，不代表首次升级、窗口启动、页面渲染、网络采集或 AI 生成的整体速度。

回归检查覆盖：旧库升级、同事务回滚、另一连接更新摘要、删除同步、长正文按需读取与完整备份恢复；缓存并发合并、过期和写入竞争；205 款商品分页、跨页搜索与完整导出；桌面实际候选分页 / 搜索、成果正文读取，以及连续切换九个页面不重复取状态。

本次最终验证：65 项 Python、59 项 Node、5 项结构检查通过；待验收包及正式程序的经营流程验收通过，模拟罗盘更新验收通过，正式程序的单实例、最小化唤起和异常恢复检查通过。
