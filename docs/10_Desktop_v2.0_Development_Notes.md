## 本次提交解决的问题

原来的经营工具与裤装罗盘客户端各自运行，找款后还要重复填写商品资料。本次将两者合为一个 Windows 桌面程序，串起“罗盘找款 → 收藏 / 候选 → 产品建档 → 利润测算 → AI 任务 → 测款记录”。

罗盘的固定裤装范围不足以覆盖其他服装业务，采集设置也不容易找到。本次支持自选类目，并从登录账号实际可见的男女装菜单读取更多子类目；固定 14 个裤装预设继续保留。增加快速读榜和最大读取数量预览，切换价位先筛选本地数据，点击更新时才重新采集，避免反复中断。

选品判断增加工厂初筛：按原统计周期的成交区间下限、点击成交转化率下限及擅长款关键词匹配。默认按钮提供成交≥100 件、转化≥3%的可调参考条件，卡片解释匹配原因和资料不足。条件匹配仍需核实面料、工艺、起订量和本厂成本。

界面调整为深色分组侧栏与浅色工作区，突出采集、筛选和结果区域。侧栏三个分组标题增大、加粗，配独立底色、分隔线及组间留白。初筛状态分别使用绿、黄、灰样式和文字，突出建档算利润等主要操作。

## 数据和接口约定

- 来源价格带及成交区间保留原始口径，不转换成精确月销量或工厂报价。未知数据保持待补；初筛按可确认的区间下限比较。
- 来源观察按账号、统计周期、类目和查询价位保留。相同商品重复建档不新增重复产品，也不覆盖手工填写的工厂成本。
- 报价页面使用实际收入和同币种成本。仅显式保存人民币测算时同步人民币成本及报价到档案；其他币种独立保存报告。
- 演示候选、产品、报告和测款记录保留演示标记；演示测款不计入真实收支汇总。
- 罗盘缓存、收藏和登录配置沿用本机 `PantsSelectionWorkbench` 目录；经营资料位于整合程序的 `data`，可用 `GARMENT_WORKBENCH_DATA` 指定位置。旧 1.3 资料通过 JSON 备份合并恢复，恢复前自动备份。
- 只有本地工作台页面可以调用经营消息接口；远程罗盘页面关闭本机消息和宿主对象。后台通过固定程序的标准输入 / 输出通信，不监听本地端口。
- 模型密钥用当前 Windows 用户的 DPAPI 加密，不通过进程参数传递；经营备份不包含密钥及浏览器登录资料。
- CLI 默认仍按原裤装范围验证。整合客户端显式启用服装扩展，采集时继续核对实际页面类目、账号和统计周期。

## 验证记录

- Python 经营与服务测试：51 项。
- 裤装规范校验与结构测试：校验通过，5 项结构测试。
- Node 测试：7 个文件、55 项，覆盖渲染、筛选、来源快照、缓存、价格、导航及工厂初筛。
- 独立程序验收：实际点击建档和保存报价，成本 20、收入 30 得到利润 10；验证重复交接、来源不代填成本、任务包与测款记录衔接。
- 模拟罗盘验收：菜单发现 15 个测试类目、新增上衣类目采集、快速读榜、完整链接、多类目、多价位、翻页、空榜、停止后保留旧数据。
- 界面验收：查看程序生成的窗口、利润页、类目及初筛截图；侧栏分组标题修改后的独立程序检查通过。

复现命令见 [整合版 README](../unified_desktop/README.md)。成品检查需正常 Windows 桌面环境，WebView2 在受限沙箱中可能无法完成初始化。截图和验收 JSON 位于本地 `desktop_app/.build/unified/tests/`。

测试使用隔离模拟页面和演示资料，未验证当前真实罗盘账号的权限及页面兼容性，未调用真实模型额度。测试中的 15 个类目仅属于夹具，不代表所有账号的可见范围。

## 构建与推送范围

仅修改桌面宿主或前端、且已有后台构建产物、后台源码及资源未变化时，可使用 `--skip-backend`。修改 `desktop_app/service.py`、依赖或打入后台的资源后应完整构建。软件正在运行时可用 `--output-dir` 和 `--archive` 构建临时待验收包，正式替换前保存资料并关闭软件。

本次 Git 提交包含源码、模板、测试、源码来源与许可、构建脚本、使用说明及开发备注。EXE、DLL、运行组件、ZIP、截图、采集缓存、真实商家数据、经营数据库、收藏、登录状态和模型密钥不进入仓库。桌面成品保留在本机；Git 推送不创建 GitHub Release 附件。
