# 服装生意工作台 2.0 · 项目整合说明

日期：2026-10-17。

## 已实现的整合

将 `product-selection-specialist-skill-1` 的罗盘选品能力与本项目的经营功能接入同一桌面窗口。采用 C# / WebView2 桌面宿主和网页选品界面，复用原 Python 的计算、档案、工作流与存储代码。原裤装项目目录未修改，源代码在当前仓库 `integrations/pants/` 保留来源提交和 MIT 许可。

操作流程：**罗盘找款 → 收藏 / 加入候选 → 建档算利润 → 产品资料与 AI 任务 → 小批量测款记录**。

- 卡片及候选中点击“建档算利润”，商品名称、链接、类目和原始统计资料自动带入。
- 收藏保留在原裤装客户端的本机收藏中，当前商品同步为经营候选；也可同步当前榜单筛选范围内的已收藏商品。
- 同一商品重复加入不会重复建档，不同周期和查询价位的观察分别保留，更新来源不会覆盖手工填写的工厂成本。
- 报价默认先显示成本、收入等核心字段，运费、包装、佣金等明细按需展开。点击保存人民币报告时，把对应成本和供货 / 零售价同步到产品档案；其他币种不覆盖人民币字段。
- 同一窗口提供档案编辑、七类 AI 工作流、成果资料、测款记录、市场 / 广告分析，以及手工款名 / 链接 / 表格收集、Excel 导入和 8 类可调参考条件。
- 深色分组侧栏配蓝色选中项；三个分组标题使用白色粗体、独立底色和分隔线。采集、筛选与结果分区明确，初筛匹配 / 资料不足 / 先观察使用绿 / 黄 / 灰样式并保留文字说明。

## 来源与数据口径

罗盘优化：选品页直接展开采集设置，支持快速读榜、最大读取数量预览和自选类目；可从已登录账号菜单读取男女装更多子类目。切换价格先筛选本地数据，点击更新后再取新榜单。固定的 14 个裤装预设继续保留；扩展类目在运行时仍核对实际页面路径与账号身份。真实账号可见类目、权限及当前页面兼容性须由本人登录验证。

新增工厂初筛：一键使用成交≥100 件、转化≥3%参考条件，也可调整下限与擅长款关键词。卡片显示匹配依据、未匹配原因及资料不足。比较原统计周期的区间下限，未知值不补零、不算匹配；这不是盈利预测，仍需核实工艺、面料、起订量和实际成本。

来源的价格带保留为价格带，成交件数、支付金额等区间保留为原始字符串。近 7 天成交区间不会转换成精确月销量，榜单价格不会自动填成工厂报价。

不同平台的市场与结算分别核对。罗盘找款只提供研究线索，Temu 全托管等业务仍按实际供货收入和所承担费用核算。演示与真实商品候选分别标记和去重，不相互覆盖。

演示标记继续进入产品档案、利润报告、关联工作流与测款记录；演示测款不计入实际支出 / 收入汇总。

原裤装项目的真实试采和商家数据没有打进整合包；首次没有本机缓存时，需要本人登录有权限的罗盘账号获取。测试仅使用明确标注的演示和模拟页面，不代表当前账号和真实平台页面已重新实测。

## 使用与升级

打开 `桌面版/服装生意工作台-2.0/服装生意工作台.exe`，或根目录 `启动服装生意工作台.cmd`。分发压缩包为 `服装生意工作台-整合版-2.0.zip`；完整解压运行组件，不要只拷贝 EXE。

需要 Windows 10/11 x64、.NET Framework 4.8 与 Microsoft Edge WebView2 Runtime；程序内已带经营后台运行组件，使用者无需自行安装 Python、Node.js 或浏览器插件。

罗盘沿用本机 `PantsSelectionWorkbench` 的登录配置、收藏和采集缓存。经营资料写入整合版的 `data`，旧 Tk 1.3 资料可以先导出 JSON，再在整合版“账号与设置”合并恢复。恢复前自动备份当前资料。不要同时在两个客户端修改同一罗盘账号的查询状态。

取消裤装收藏不会删除已经形成的经营候选或工厂档案；不准备继续做的款，可以在候选资料中标记“放弃”。替换程序时保留原经营数据目录，开发验收使用隔离资料。

构建只收集明确的程序文件和说明，不包含经营数据库、用户备份、模型密钥、真实榜单、收藏和登录状态。两个项目和第三方依赖的许可保留在包内。
